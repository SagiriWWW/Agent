# 当前项目计划（对话交接版）

更新时间：2026-07-02

这份文档用于给新的对话或协作者快速建立上下文。当前项目不是一个已经完成的生产级多智能体决策系统，而是一个已经可运行的 Agent 工具箱 MVP：以 Agent 编排为主线，调用本地可信工具完成飞行遥测数据画像、规则库解析、规则命中、关联规则挖掘、结果校验、报告生成和证据链记录。截至 2026-07-02，项目已经完成 `rules_v2.yaml` 在 30 个 `last_avg` 数据集上的全量批量验证，并生成 v1/v2 规则版本对比报告、v2 专家复核包和关键命中样例导出。后续工作必须从“围绕当前数据集调规则”转向“跨客户数据集的 Schema 语义映射和规则适配”，避免对 `last_avg` 样例过拟合。

## 一句话交接

当前项目应被理解为“单 Agent 编排器 + 本地工具箱 + 证据链 + Web/CLI 演示 + 批量规则复核 + 泛化适配预备层”的飞行遥测分析 MVP。它已经能离线跑通确定性演示流程，并能通过批量验收比较规则版本稳定性；但客户后续数据很可能与当前 `last_avg` 样例字段结构差异较大，因此下一阶段重点是数据接入泛化、字段语义映射和规则适配，而不是继续只针对当前数据集调阈值。多智能体拆分、本地 8B LLM、RAG 向量库、因果图和流式遥测接入都属于下一阶段或更长期能力，不是当前已实现状态。

## 给新对话的工作原则

1. 先保持当前 MVP 稳定，不要为了“多智能体完整架构”一次性推翻现有 `AgentRunner + ToolExecutor`。
2. 新能力优先以本地工具形式加入 `ToolExecutor`，让报告、证据链和测试自然复用已有机制。
3. 不要把 FP-growth 或 Pearson 相关性描述成因果推断。
4. 不要声称当前已经部署本地 8B LLM、向量数据库或 RAG。
5. 所有新增分析结论都应绑定工具输出、规则来源、数据文件和证据链节点。
6. 离线 deterministic demo 是当前项目的重要兜底能力，后续即使接本地 LLM 也应保留。
7. 不要继续围绕当前 `dataset/last_avg` 样例反复调阈值；后续客户数据可能字段、单位、结构和业务阶段都不同，新增工作应优先提升 Schema 映射、规则适配和不兼容数据识别能力。
8. 人工复核意见进入全局候选前必须同时满足跨运行确认、跨数据指纹、映射回归通过和无驳回冲突；不要把单次确认或单数据集可执行结果沉淀为全局配置。

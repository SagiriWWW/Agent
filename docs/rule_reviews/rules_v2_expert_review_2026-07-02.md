# 规则库 v2 专家复核包

生成日期：2026-07-02

## 1. 复核目的

本文档用于把 `examples/rules_v2.yaml` 的全量批量验证结果整理为专家复核材料。它不是最终业务定稿，也不声称当前规则已经具备故障诊断准确率，只用于回答一个工程验收问题：

同一批 `dataset/last_avg/` 数据上，v2 规则库相比 v1 是否减少明显过宽或局部高命中的规则，同时保持 Agent 工具链、报告和证据链稳定。

- Web 样例入口：`/batches/07b79fd7-b0dc-4534-8cb6-6fa17c8ce012/hit-samples`

## 3. 总体结论

v2 规则库可以作为下一阶段专家复核版本。

理由如下：

- v2 全量批次完成 `30/30`，通过 `30`，失败 `0`。
- v2 规则稳定性标签为：`相对稳定 6`，`稀疏事件 1`。
- v1 中的 `R001` 从“疑似过宽”改善为“相对稳定”。
- v1 中的 `R002` 从“局部高命中”改善为“相对稳定”。
- 未调整的 `R003`、`R004`、`R005`、`R006` 保持基本持平。
- `R007` 阈值收窄后仍是稀疏事件，应保留为事件型规则并交由专家确认业务解释。

需要强调：v2 只是规则命中分布更稳定，并不等同于真实故障诊断准确率提升。

## 5. 专家重点复核问题

1. `R001` 的主电池余量阈值 `50` 是否符合当前任务场景的安全裕度。
2. `R002` 的电压阈值 `21700` 是否需要结合电池类型、串数、单位和负载状态重新标定。
3. `R005` 虽然标签为相对稳定，但部分数据集最高命中率达到 `100.0%`，是否说明该规则需要按环境温度或传感器状态分场景解释。
4. `R007` 是否应继续作为低速或接近静止事件线索，而不是风险告警。
5. 当前规则是否需要补充“适用飞行阶段”，例如起飞、巡航、悬停、降落、地面静止。

## 6. 当前可采纳建议

- 将 `examples/rules_v2.yaml` 标记为“专家复核候选版本”。
- 不直接覆盖 `examples/rules.yaml`，继续保留 v1 作为基线。
- 后续新增规则或调整规则时，必须继续通过批量验收和版本对比报告验证。
- 对外展示时，可以说明 v2 在 30 个 `last_avg` 数据集上通过了工程稳定性验证，但不能表述为故障诊断准确率验证。

## 7. 边界说明

- 本复核包只基于当前 30 个 `last_avg` 数据集。
- 当前数据的 `label` 全部为 0，`diagnosis` 为空，因此无法进行监督准确率评价。
- FP-growth 和 Pearson 相关性只能提供共现与相关线索，不能证明因果关系。
- 当前离群值检查只是数据质量提示，不等同于独立异常检测模块。
- v2 阈值来自当前批量命中分布优化，仍需领域专家确认业务合理性。

## 8. 下一步建议

当前已经完成“关键命中样例导出”。v2 批次共导出 4 条重点规则、20 组数据集样例、100 行样例，覆盖 `R001`、`R002`、`R005`、`R007`。

专家复核时建议优先查看：

- `R001` 命中率较高的数据集样例，判断 `50` 的电池余量阈值是否合理。
- `R002` 命中率较高的数据集样例，判断 `21700` 的电压阈值是否合理。
- `R005` 命中率达到或接近 100.0% 的数据集样例，判断是否需要加入环境或传感器状态条件。
- `R007` 最高命中率对应的数据集样例，判断低速事件是否对应起降、悬停或停滞状态。

下一步建议推进 Schema 层扩展：为关键字段补充单位、分箱策略、字段别名和适用飞行阶段。这样专家对阈值的复核意见可以沉淀回结构化配置，而不是停留在报告文字里。
